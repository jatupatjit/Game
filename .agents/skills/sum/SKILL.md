# Task Summary (/sum)

สร้างรายงานสรุปผลการทำงานของ Task ปัจจุบันอย่างกระชับ ชัดเจน และมีหลักฐานอ้างอิงจริง (Evidence-backed) หากผู้ใช้มีข้อความระบุจุดที่ต้องการเน้นต่อท้ายคำสั่ง (เช่น `/sum เน้นเรื่อง MCP`) ให้โฟกัสเรื่องนั้นเป็นพิเศษโดยยังคงโครงสร้างสรุปหลักไว้ครบถ้วน

## เงื่อนไขการเรียกใช้ (Invocation Triggers)
ทำงานทันทีเมื่อได้รับข้อความเหล่านี้:
- `/sum` หรือ `$sum`
- `ขอสรุป` หรือ `สรุปให้หน่อย`
- `สรุปงาน` หรือ `ขอสรุปงาน`
- รูปแบบผสมที่มีหัวข้อเน้น เช่น `/sum เน้นเรื่องการตั้งค่า MCP`, `ขอสรุป เน้นส่วน Network`

## การรวบรวมหลักฐานและตรวจสอบ (Evidence Set)
- รวบรวมจากการสนทนาของ Task ปัจจุบัน, คำสั่งที่รันจริง, ผลลัพธ์จาก Tool และ Acceptance criteria
- อ้างอิงไฟล์ที่มีการสร้าง แก้ไข หรือลบจริงใน Task นี้
- รายงานเฉพาะการทดสอบหรือคำสั่งที่รันจริงเท่านั้น ห้ามเดาหรือสรุปผลลอยๆ

## สถานะงาน (Status)
เลือก 1 สถานะพร้อมระบุเหตุผลสนับสนุน:
- **เสร็จ (Complete)**: ผลลัพธ์บรรลุตามเป้าหมายเรียบร้อย ไม่เหลืองานที่ต้องทำค้าง
- **เสร็จบางส่วน (Partial)**: งานส่วนใหญ่สำเร็จ แต่ยังเหลืองานหรือการทดสอบบางส่วน
- **ติดขัด (Blocked)**: ไม่สามารถดำเนินการต่อได้เนื่องจากรอข้อมูล การยืนยัน หรือการตัดสินใจจากผู้ใช้

## รูปแบบการนำเสนอ (Summary Headings)
ให้ตอบเป็นภาษาไทยอย่างกระชับตามหัวข้อมาตรฐานดังนี้:

1. **สถานะ**: ระบุสถานะและเหตุผล 1 ประโยค
2. **เป้าหมายของงาน**: เป้าหมายและผลลัพธ์ที่ได้
3. **สิ่งที่ทำไปแล้ว**: รายการการดำเนินการสำคัญที่ทำสำเร็จ
4. **สิ่งที่เปลี่ยนแปลง**: พฤติกรรมที่เปลี่ยนไป พร้อมแสดงไฟล์สำคัญที่สร้าง/แก้ไข/ลบ (ลิงก์ไฟล์ที่คลิกได้)
5. **การตรวจสอบที่ทำแล้ว**: ผลการรันคำสั่ง ตรวจสอบความถูกต้อง หรือการทดสอบจริง
6. **สิ่งที่ควรรู้ / ข้อควรระวัง**: สิ่งที่ผู้ใช้ควรทราบ การตั้งค่าเพิ่มเติม หรือขั้นตอนที่ต้องทำต่อ
